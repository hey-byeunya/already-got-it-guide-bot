# 판정 — 무엇을 모델에게 묻고 무엇을 묻지 않았나

## 나눈 기준

**뜻을 읽어야 하는 것만 모델에게 맡깁니다.** 셀 수 있는 것은 프로그램이 셉니다.

| 무엇을 재는가 | 누가 | 왜 |
|---|---|---|
| 인용을 했는가 | **프로그램** | 본문에서 `[숫자]` 를 찾으면 끝난다 |
| 지어낸 인용인가 | **프로그램** | 근거가 5개인데 `[7]` 이면 범위 밖이다 |
| 내부 ID 가 새어 나왔는가 | **프로그램** | 본문에 `HELP-` 가 있는가 |
| 절차형으로 답했는가 | **프로그램** | 번호 목록 2단계 이상 + 화면 이름 |
| 기대한 도움말을 인용했는가 | **프로그램** | 인용 번호를 청크 ID 로 되짚으면 된다 |
| 답이 근거에서 나왔는가 | 판정 모델 | 뜻을 읽어야 한다 |
| 지어낸 사실이 있는가 | 판정 모델 | 뜻을 읽어야 한다 |
| 정당한 거절인가 | 판정 모델 | 뜻을 읽어야 한다 |

## 왜 `cited` 를 판정 모델에게서 빼앗았나

`dev-bot` 이 그것을 모델에게 물었고, 측정한 실패 108건 중 **42건이 그 판정의 실패**였습니다. 두 번 고쳐 보고 두 번 다 되돌렸습니다.

| 시도 | 결과 |
|---|---|
| 생성 온도를 0 으로 | 판정 정확도 0.74 → **0.48** |
| 출처 표기를 `[AG-004]` 로 통일 | 표기는 100% 맞았는데 0.74 → **0.59** |

어느 쪽으로 건드려도 나빠졌습니다. 남는 결론은 하나입니다 — **문제는 문구가 아니라, 답을 만든 것과 같은 작은 모델에게 판정을 맡긴 구조 자체입니다.**

여기서는 그 일을 [`citation.ts`](../app/src/lib/citation.ts) 가 합니다. `node scripts/check_citation.ts` 가 13가지 경우로 세는 법을 시험합니다 — 붙여 쓴 인용 `[1][2]`, 쉼표로 묶은 `[1, 3]`, 마크다운 링크를 인용으로 세지 않기, 범위 밖 번호, 한 줄에 이어 쓴 단계까지.

**판정을 모델에게서 가져왔으니, 세는 법이 맞는지는 이제 우리 책임입니다.** 그래서 시험을 붙였습니다.

## 그래서 판정은 믿을 만해졌나 — 아니다

남은 셋(`grounded`·`noHalluc`·`refusal`)은 여전히 **답을 만든 것과 같은 `qwen3.5:2b`** 가 판정합니다. 독립 심사가 아닙니다.

실험 180건에서 **판정이 스스로 모순된 것이 109건**입니다 — 「지어낸 사실 있음」이라고 하면서 80점 이상을 준 경우입니다. 형식이 깨져 판정을 아예 못 받은 것도 17건입니다.

| 지표 | S0 | 무엇을 뜻하는가 |
|---|---|---|
| 환각 없음 비율 | 0.17 | 판정이 답의 83%에 「지어낸 사실 있음」을 붙였다 |
| 배지와 점수가 다른 말 | 109건 | 그러면서 점수는 80~95점을 줬다 |

**이 숫자를 「모델이 그만큼 지어냈다」로 읽으면 안 됩니다.** 판정 자체가 흔들립니다. 그래서 화면에서도 판정 배지는 검토 모드 뒤에 두고, 고객 모드에는 「한 번 더 확인이 필요합니다」 한 줄만 둡니다.

## 판정이 실패해도 답변은 남는다

형식이 깨진 응답이 와도 **답변과 참고한 도움말은 지우지 않습니다.** 판정 자리에 실패 표시만 남깁니다. 판정은 답변을 다시 읽게 돕는 보조 장치이지, 답변이 화면에 남을 조건이 아닙니다.

## 사람 피드백

「도움됐어요 / 아니에요」를 자동 판정과 **나란히** 봅니다. 어긋나면 검토 모드에서 그 사실을 드러냅니다 — 판정이 놓친 유용성이거나, 고객이 놓친 근거입니다. 어느 쪽이든 다시 읽어야 할 자리입니다.

서버가 없으므로 「피드백 내려받기」로 파일을 받습니다. 브라우저에 저장하지도 않습니다 — 그 브라우저 안에만 갇혀서 모아 볼 수 없기 때문입니다. **새로고침하면 사라진다는 사실을 버튼 옆에 적어 두었습니다.**
