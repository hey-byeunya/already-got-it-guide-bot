# 실패 정리 — 어느 단계가 원인이었나

```bash
node scripts/collect_failures.ts   # → data/failures.json
```

원자료 **225건**(5세팅 × 15문항 × 3회)을 사람이 정한 규칙으로 나눴습니다. 자동 분류를 모델에게 맡기면 **또 하나의 못 믿을 판정**이 생깁니다.

단계로 나누는 이유: 「답이 틀렸다」는 고칠 수 없고, 「검색이 엉뚱한 것을 올렸다」나 「인용 번호를 아무렇게나 붙였다」는 고칠 수 있습니다.

| 단계 | 유형 | 건수 | 누가 잡았나 |
|---|---|---|---|
| **검색** | 기대한 도움말이 근거에 없음 | **0** | 프로그램 |
| 생성 | 절차를 물었는데 절차형이 아님 | 61 | 프로그램 |
| 생성 | 근거는 올라왔는데 다른 것을 인용 | 70 | 프로그램 |
| 생성 | 인용을 아예 하지 않음 | 28 | 프로그램 |
| 생성 | 없는 번호를 인용 (지어낸 출처) | 2 | 프로그램 |
| 생성 | 내부 문서 ID 노출 | 1 | 프로그램 |
| 거절 | 도움말 밖인데 답해 버림 | 18 | 판정 |
| 판정 | **배지와 점수가 다른 말** | **141** | 사람 |
| 판정 | 형식이 깨진 응답 | 19 | 프로그램 |

합계 340건 (한 답이 여러 유형에 걸릴 수 있습니다) · 그중 **181건(53%)을 프로그램이 잡았습니다.**

## 가장 또렷한 것 — 검색은 한 번도 실패하지 않았다

**225건에서 「기대한 도움말이 근거에 없음」 0건.**

기대한 도움말은 언제나 근거 안에 올라왔습니다. 그런데 답변이 그것을 인용하지 않은 경우가 **70건**입니다.

**단계로 나눠 보지 않았다면 검색을 손보고 있었을 것입니다.** "챗봇이 틀렸다"는 관찰만으로는 어디를 고쳐야 하는지 알 수 없습니다. 하이브리드 검색·임베딩 접두어·BM25 가중치를 며칠 만졌어도 이 숫자는 하나도 움직이지 않았을 것입니다.

## 생성 실패 162건 — 프롬프트로 고쳐지지 않았다

| 시도 | 결과 |
|---|---|
| 형식을 지시한다 (S0) | 절차형 **0/5** |
| 형식 지시를 뺀다 (S1) | 절차형 1/5 — **뺀 쪽이 낫다** |
| 근거를 15개 → 8개로 (S2) | 기대 도움말 인용 0.67 → **0.67**, 그대로 |
| 인용 요구를 맨 끝으로 (S3) | 전부 흔들림 안 |
| 모델을 3B 로 (S4) | 절차형 2/5 로 **올라가고**, 인용은 11 → **1.7 로 무너짐** |

**어느 문구로 건드려도 나아지지 않았고, 모델을 키우자 다른 것이 무너졌습니다.**

이건 `dev-bot` 이 판정에서 겪은 것과 같은 모양입니다. 그쪽은 두 번 고쳐 보고 둘 다 되돌린 뒤 "문제는 문구가 아니라 구조"라고 적었습니다. 여기는 다섯 번 재고 같은 자리에 왔습니다.

## 판정 실패 160건 — 판정을 못 믿는다는 증거

**「배지와 점수가 다른 말」이 141건**입니다 — 「지어낸 사실 있음」이라고 판정하면서 80점 이상을 준 경우입니다.

| 지표 | 값 | 어떻게 읽어야 하나 |
|---|---|---|
| 환각 없음 비율 | 0.13~0.31 | **「모델이 그만큼 지어냈다」로 읽으면 안 된다** |
| 배지와 점수가 다른 말 | 141건 | 판정이 스스로 모순된다 |
| 형식이 깨진 응답 | 19건 | 판정을 아예 못 받았다 |

판정은 답을 만든 것과 **같은 `qwen3.5:2b`** 가 합니다. 독립 심사가 아닙니다.

**그래서 이 저장소는 판정에서 셀 수 있는 것을 전부 빼앗았습니다.** 인용·지어낸 번호·내부 ID 노출·절차형·기대 도움말 인용은 프로그램이 셉니다. 위 표에서 「누가 잡았나」가 「프로그램」인 줄은 다시 세도 같은 값이 나옵니다. `dev-bot` 은 실패 108건 중 42건이 판정의 실패였고, 그래서 나머지 지표를 읽을 수 없었습니다.

## 고치지 못한 것

| 무엇 | 왜 |
|---|---|
| **답변 품질** | 프롬프트로 안 되고, 모델을 키우면 인용을 잃는다. 다음 회차의 첫 일이다 |
| **원문의 부정을 뒤집는 것** | `dev-bot` 에서 원문 인용을 요구해도 3/12 그대로였다. **못 고쳐서 표시만 한다** |
| 「고객센터 전화번호」에 약한 근거 경고 | 유사도 0.578 로 기준 0.55 를 넘는다. 기준을 0.6 으로 올리면 켜지지만, 그러면 그 숫자의 근거가 질문 15개뿐이 된다 |
| 판정의 신뢰도 | 같은 2B 가 판정한다. 셀 수 있는 것은 이미 빼앗았고, 남은 셋은 뜻을 읽어야 한다 |

## 다음에 잴 것

1. **3B 로 답을 만들되 인용을 어떻게 붙일 것인가.** 답변 품질과 인용이 서로 다른 모델에 갈렸다는 것을 알았다. 지금까지의 결론대로라면 그 답은 모델에게 더 세게 부탁하는 것이 아닐 가능성이 높다
2. 약한 근거 기준값 — 질문을 더 넣어 다시 재고 나서 정한다
3. 판정 모델을 답변 모델과 다른 것으로 분리했을 때 「배지와 점수가 다른 말」 141건이 줄어드는지
