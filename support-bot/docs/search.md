# 검색 — 하이브리드와 모델 없이 도는 길

## 규칙

명세대로 고정했습니다. 실험(S2)에서만 바꿔 재고, 결과는 [실험 기록](rubric.md)에 있습니다.

| 무엇 | 값 |
|---|---|
| 코사인 상위 | 10 |
| 미중복 BM25 상위 | 5 |
| BM25 정규화 | 그 검색의 최고 점수로 나눠 0~1 |
| 약한 근거 기준 | 최고 코사인 0.55 미만 |
| 결과를 버리는가 | **버리지 않는다.** 표시만 올린다 |

버리지 않는 이유는, 버리면 검색이 어떻게 실패했는지 알 수 없고, 그러고도 평소와 같은 자신감으로 답하면 약한 연관을 사실처럼 말하게 되기 때문입니다.

## 한국어를 어떻게 잘랐나

한국어는 조사가 붙어 「수량을」과 「수량」이 다른 낱말이 됩니다. 브라우저에서 형태소 분석기를 쓸 수 없으므로, 한글은 **글자 2개씩(bigram)** 으로 잘라 조사가 붙어도 겹치는 부분이 남게 했습니다. 영문·숫자는 낱말 그대로 둡니다.

## 모델 없이 도는 검색 — `keywordOnlySearch`

**배포 주소에서 답변 생성이 막힙니다.** 페이지는 HTTPS 인데 Ollama 는 HTTP 라, 브라우저가 그 요청을 막습니다(사설망 접근). 그렇다고 화면이 아무것도 못 하면 링크만 열어 본 사람은 빈손으로 돌아갑니다.

BM25 는 낱말이 겹치는 정도만 보므로 **모델이 필요 없습니다.** 정적 JSON 과 브라우저 계산만으로 돕니다.

배포 주소에서 직접 확인했습니다.

> "유통기한 알림이 오나요?" → **195MB 를 받지 않고** 1위로 「자주 묻는 질문 · 사용기한이 다가오면 알림이 오나요」

한계를 숨기지 않습니다 — 표현이 다르면 놓칩니다. 「다 쓴 물건」과 「사용 완료」처럼 뜻은 같고 낱말이 다른 질문은 벡터 검색이라야 잡힙니다. 화면에도 그렇게 적어 두었습니다.

## 검색이 실패한 적이 있는가

실험 4세팅 × 3회 × 15문항 = **180건에서 「기대한 도움말이 근거에 없음」 0건.**

기대한 도움말은 언제나 근거 15개 안에 올라왔습니다. 그런데 답변이 그것을 인용하지 않은 경우가 **41건**입니다([실패 정리](failures.md)).

**이 대비가 이 프로젝트에서 가장 또렷한 결과입니다.** 검색은 제 일을 다 했고, 실패는 전부 그다음에서 났습니다. "챗봇이 틀렸다"를 단계로 나눠 보지 않았다면 검색을 손보고 있었을 것입니다.
