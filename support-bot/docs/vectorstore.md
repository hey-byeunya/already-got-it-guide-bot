# 벡터스토어 — 만든 방법과 확인한 것

```bash
python3 scripts/build_chunks.py                    # 도움말 → data/chunks.json (청크 26개)
node scripts/embed-docs-browser-path.mjs --prefix  # → app/public/help-docs.json (0.44MB)
```

| 확인 | 결과 |
|---|---|
| 768차원 | 26/26 |
| L2 정규화 (‖v‖=1) | 26/26 |
| 필드 보존 | `id · text · url · doc · section` + `vector` |
| 앵커 도달 | 26/26 |

`doc` 필드가 dev-bot 에 없던 것입니다. 화면에 「위시리스트 · 샀을 때 옮기기」로 보여 줄 **사람이 읽는 이름표**입니다. dev-bot 은 `AG-004` 를 그대로 보여 줬습니다.

## 브라우저와 Node 가 같은 공간인가

문서 벡터는 Node 가 미리 만들고, 질문 벡터는 브라우저가 그때그때 만듭니다. 둘이 다른 방식이면 숫자는 나오지만 **비교할 자리를 잃습니다.**

같은 모델 파일(`model_no_gather_q4.onnx`), 같은 실행(wasm), 같은 mean pooling, 같은 L2 정규화, 그리고 EmbeddingGemma 가 요구하는 접두어까지 맞췄습니다. 화면의 「임베딩 대조」 버튼이 언제든 다시 잽니다 — 기준점은 `app/public/parity-anchor.json` 입니다.

## 받아 오는 방식을 고쳤다 — 커밋 SHA 로 받는다

도움말을 `main` 에 머지한 직후 청크를 다시 만들었는데 **옛 파일이 왔습니다.** `raw.githubusercontent.com` 이 브랜치 이름으로 받으면 몇 분간 캐시를 줍니다. `main` 에는 분명히 들어가 있었습니다.

그래서 브랜치 이름을 **커밋 SHA 로 먼저 풀어서** 받습니다.

- 캐시를 타지 않는다
- **어느 커밋의 도움말로 만든 청크인지 남는다** (`data/chunks-source.json`)

두 번째가 덤이 아닙니다. 자료가 바뀌었는지 되짚을 때 "그때 무엇을 보고 만들었나"를 알 수 있어야 합니다.

## 유사도 분포 — 약한 근거 기준값을 그대로 쓸 수 있는가

평가 세트 15개(게이트 2개 제외)를 S0 세팅으로 3회 돌려 최고 유사도를 쟀습니다.

| 무리 | 개수 | 최저 | 최고 |
|---|---|---|---|
| 도움말에 있는 질문 | 33 | **0.679** | 0.843 |
| 도움말에 없는 질문 | 6 | 0.549 | **0.578** |

**두 무리 사이 틈 +0.101.**

dev-bot 은 같은 자리에서 틈이 **0.016** 이었고, "질문이 더 오면 다시 겹칠 수 있다"고 경고를 붙여야 했습니다. 여기는 6배 넓습니다. **자료를 고객의 언어로 새로 쓴 것이 검색에도 효과가 있었습니다** — 개발 문서는 어느 질문에나 비슷하게 가까웠는데, 고객용 문서는 관계없는 질문과 확실히 멀어집니다.

### 기준값 0.55 는 바꾸지 않았다

| 질문 | 최고 유사도 | 경고가 켜지는가 |
|---|---|---|
| "내일 날씨 어때?" | 0.549 | ✅ 켜짐 |
| "고객센터 전화번호가 어떻게 되나요?" | 0.578 | ❌ 안 켜짐 |
| 답할 수 있는 질문 중 가장 낮은 것 | 0.679 | — (잘못 켜짐 **0건**) |

전화번호 질문에 경고가 켜지지 않습니다. 기준값을 0.6 으로 올리면 둘 다 켜지고 잘못 켜짐도 0건입니다 — 틈이 0.101 이라 여유가 있습니다.

**그래도 올리지 않았습니다.** 올리면 그 숫자가 왜 그 값인지 설명할 근거가 **질문 15개뿐**이 됩니다. 명세가 준 0.55 를 그대로 두고, 켜지지 않는 경우가 있다는 사실을 여기 적어 둡니다. 질문을 더 넣어 다시 잰 뒤에 정할 일입니다.
