# 화면 — 한 페이지, 두 시선

앱: [`app/`](../app) (Vite · React · TypeScript, `base: './'`)

기본은 **고객 모드**입니다. 유사도·검색 방법·판정 배지·인용 계수는 「자세히 보기」 뒤로 물러납니다(주소에 `?review` 를 붙여도 열립니다).

지우지는 않았습니다 — **검토할 수 없는 챗봇은 근거를 보여 준다고 말할 자격이 없습니다.**

| 영역 | 고객 모드 | 검토 모드에서 더 보이는 것 |
|---|---|---|
| 첫 화면 | 인사 + 자주 묻는 질문 6개 + 사용 조건 | — |
| 연결 상태 | 「지금은 상담 답변을 만들어 드릴 수 없습니다」 + 재시도 | Ollama 연결 배너 |
| 답변 | 결론 → 절차 → 주의 (스트리밍, 멈춤 가능) | — |
| 참고한 도움말 | 「위시리스트 · 샀을 때 옮기기」 + 원문 열기 | ID · 검색 방법 · 점수 |
| 검색된 도움말 | 가까운 5개 | 15개 전부 + 점수 해석 주의 |
| 판정 | 한 줄 | grounded·noHalluc·refusal 배지 + 인용 계수 + 절차형 |
| 호출 전 검사 | 「도와드릴 수 없습니다」 + 앱 화면 경로 | 어느 규칙이 막았는지 |

## 「참고한 도움말」은 프로그램이 붙인다

모델이 쓰지 않습니다. 본문의 `[1]` 번호를 프로그램이 읽어 도움말 이름과 원문 링크를 잇습니다. **모델이 쓰면 지어낼 수 있고, 지어낸 출처는 없는 출처보다 나쁩니다.**

답변이 아무것도 가리키지 않으면 그 자리를 비우지 않고 이렇게 적습니다.

> **이 답변은 도움말을 가리키지 않았습니다.** 아래는 이 질문으로 검색된 도움말이지, 답변이 근거로 밝힌 것이 아닙니다. **매끄럽게 읽히는 것과 근거가 있는 것은 다릅니다.**

비워 두면 고객은 근거가 있는데 표시만 안 된 것으로 읽습니다.

## 써 보다 고친 것 넷

문서를 보고 만든 것이 아니라 **실제로 눌러 보다** 찾은 것들입니다.

| 무엇 | 어디서 찾았나 | 어떻게 고쳤나 |
|---|---|---|
| 부정문 경고가 근거 15개 전체에서 11문장을 뽑아 **답변 위에** 쌓임 | 로컬 | 답이 **실제로 인용한** 근거만, 답 아래로, 접어서 |
| 그 문장에 마크다운 별표가 새어 나옴 (`**바코드 스캔은…`) | 로컬 | `findNegations` 가 마크다운을 벗김 |
| `</think>` 가 답변에 새어 나옴 | 로컬 (평가 세트 C02) | `stripThinking` — 태그와 뜻 없는 꼬리 줄까지 |
| 안내문의 `[이미 있어](https://…)` 가 **글자 그대로 보임** | **배포 주소** | `AnswerBody` 가 링크도 살림 |

마지막 것은 로컬에서는 못 찾았을 문제입니다. 로컬에서는 게이트 답변을 눌러 볼 이유가 없었는데, **배포 주소에서는 답변 생성이 막히니 게이트 답변이 가장 자주 보는 답이 되면서** 드러났습니다. 고객이 갈 곳을 알려 주는 문장인데 정작 갈 수가 없었습니다.

첫 번째에서 배운 것: **알림이 답을 가리면 알린 뜻이 없습니다.** 경고를 붙이는 것과 경고가 읽히게 두는 것은 다른 일입니다.
