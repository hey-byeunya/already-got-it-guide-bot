# 이미 있어 고객센터 챗봇

[이미 있어](https://already-got-it.vercel.app)를 쓰다 막혔을 때, **공개 도움말을 근거로** 안내하는 상담 챗봇입니다. 답할 때마다 **어느 도움말을 참고했는지** 함께 보여 줍니다.

같은 저장소의 [`dev-bot/`](../dev-bot)은 같은 서비스를 다루는 **개발자용** 챗봇입니다. 무엇을 이어받고 무엇을 바꿨는지는 [PRD 9절](PRD.md)에 있습니다.

## 쓰기 전에 확인할 것

1. 질문을 입력하시면 관련 도움말을 찾아 드립니다. 여기까지는 아무 준비도 필요하지 않습니다.
2. 상담 답변까지 받으시려면 내 컴퓨터에서 Ollama를 실행하고 `qwen3.5:2b`를 준비합니다.
3. 답변을 처음 받으실 때 검색용 모델을 약 195MB 내려받습니다. 한 번 받으면 다음부터 기다리지 않습니다.

```bash
ollama pull qwen3.5:2b
```

```bash
cd support-bot/app && npm install && npm run dev
# http://localhost:5174 — 페이지와 Ollama가 같은 http 라서 막히지 않습니다
```

> ⚠️ 배포 주소는 HTTPS이고 Ollama는 HTTP라, 브라우저가 그 요청을 막습니다. `OLLAMA_ORIGINS`를 설정해도 막힙니다. 답변까지 받으시려면 저장소를 내려받아 `npm run dev`로 직접 띄우세요.

```bash
# macOS — 배포 주소에서 시도해 보시려면
launchctl setenv OLLAMA_ORIGINS "https://hey-byeunya.github.io"
# 설정 뒤 Ollama를 재시작합니다
```

Chrome과 Edge를 권장합니다. Safari에서는 Ollama 연결과 임베딩이 불안정할 수 있습니다.

## 물을 수 있는 것과 없는 것

| 물을 수 있다 | 도와드릴 수 없다 |
|---|---|
| 위시에 담아둔 걸 있템으로 옮기는 방법 | 고객님 계정 안의 정보 (내 있템이 몇 개인지) |
| 카테고리·수량·상태 입력 규칙 | 계정·비밀번호를 대신 조작하기 |
| 쓴템 탭의 뜻과 되돌리는 방법 | 데이터를 대신 바꾸기 |
| D-day 배지 네 단계의 의미 | 도움말에 없는 이야기 (오늘 날씨 등) |
| **없는 기능** (알림·바코드·통계) | |

마지막 줄이 이 챗봇의 특징입니다. **"유통기한 알림이 오나요?"에 「도움말에 없습니다」가 아니라 근거를 가지고 「오지 않습니다」라고 답합니다.** 없다는 사실을 도움말에 적어 두었기 때문입니다. 「없습니다」는 거절이 아니라 답입니다.

## 근거 자료

`already-got-it` 저장소의 [`docs/help/`](https://github.com/hey-byeunya/already-got-it/tree/main/docs/help) 문서 7개를 **절 단위로 잘라 청크 26개**로 만들었습니다.

| 도움말 | 청크 | 도움말 | 청크 |
|---|---|---|---|
| 시작하기 | 4 | 찾기와 D-day | 3 |
| 있템 등록 | 4 | 계정과 내 데이터 | 3 |
| 위시리스트 | 3 | 자주 묻는 질문 | 6 |
| 쓴템 | 3 | **합계** | **26** |

이 도움말은 이 프로젝트에서 **새로 작성해 공개한 것**입니다. 기존 공개 문서(`PRD.md`·`docs/rules/*.md`·`supabase/migration.sql`)를 그대로 쓰지 않은 이유는 하나입니다 — 거기엔 `mark_wishlist_purchased` RPC 이름과 SQL 제약이 들어 있어서, **고객이 출처를 열면 자기가 읽을 수 없는 문서를 만납니다.** 그러면 출처를 보여 주는 의미가 사라집니다.

어느 문장이 어느 개발 문서에서 왔는지는 [수집 기록](docs/corpus.md)에 절 단위 대조표로 남겼습니다.

## 설계 결정 요약

**인용 여부를 프로그램이 셉니다.** `dev-bot`은 "답변에 출처 표시가 있는가"를 판정 모델에게 물었고, 측정한 실패 108건 중 **42건이 그 판정의 실패**였습니다. 온도를 0으로 고정해도(0.74 → 0.48), 표기를 통일해도(0.74 → 0.59) 나빠지기만 했습니다. 글자를 찾으면 끝나는 일이라, 여기서는 [`citation.ts`](app/src/lib/citation.ts)가 셉니다 — 인용 번호, 지어낸 번호, 내부 ID 노출, 절차형 여부까지. 판정 모델에는 **뜻을 읽어야 하는 셋**(근거성·환각·정당한 거절)만 남겼습니다.

**답변 본문에 내부 문서 ID를 쓰지 않습니다.** 고객이 읽을 답변에 `HELP-WISH-02` 가 있으면 그것 자체가 고객센터답지 않습니다. 본문은 `[1]` 번호를 쓰고, 번호와 도움말 이름을 잇는 「참고한 도움말」은 **모델이 아니라 프로그램이 붙입니다.** 모델이 쓰면 지어낼 수 있고, 지어낸 출처는 없는 출처보다 나쁩니다.

**한 화면 두 시선입니다.** 기본은 고객 모드이고, 유사도·검색 방법·판정 배지는 「자세히 보기」 뒤로 물러납니다. 지우지는 않았습니다 — 검토할 수 없는 챗봇은 근거를 보여 준다고 말할 자격이 없습니다. 주소에 `?review` 를 붙여도 열립니다.

**Ollama가 없어도 멈추지 않습니다.** BM25 검색은 모델이 필요 없으므로, 195MB를 받지 않고도 관련 도움말을 찾아 드립니다. 배포 주소를 링크로만 연 사람도 "이 질문의 답은 이 도움말에 있습니다"까지는 받습니다.

## 만드는 방법

```bash
python3 scripts/build_chunks.py                    # 도움말 → 청크 26개 (4가지 검사)
node scripts/embed-docs-browser-path.mjs --prefix  # 청크 → 벡터스토어
```

`build_chunks.py` 는 매번 네 가지를 검사하고, 하나라도 어긋나면 **파일을 쓰지 않고 멈춥니다.**

| 검사 | 왜 |
|---|---|
| 기대한 절 제목이 아직 있는가 | 제목이 바뀌면 ID와 앵커의 짝이 깨진다 |
| 각 청크가 120자 이상인가 | 짧은 조각은 검색에 안 걸리고, 걸려도 답할 재료가 부족하다 |
| 출처 주소가 겹치지 않는가 | 두 청크가 같은 자리를 가리키면 근거를 구별할 수 없다 |
| **앵커가 실제로 그 자리로 가는가** | 링크는 열리는데 앵커만 죽는 실패는 **눈으로 보이지 않는다** |

브랜치 이름 대신 **커밋 SHA로 받습니다.** 머지 직후 raw CDN이 몇 분간 옛 파일을 주는 일을 실제로 겪었습니다. 어느 커밋의 도움말로 만든 청크인지는 `data/chunks-source.json` 에 남습니다.

