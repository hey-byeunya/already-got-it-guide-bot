# C단계 — 벡터스토어와 검색 스팟체크

```bash
node scripts/embed-docs-browser-path.mjs                            # 문서 벡터
node scripts/embed-docs-browser-path.mjs --queries data/spotcheck-queries.json
python3 scripts/check_retrieval.py                                  # 검색 스팟체크
```

산출물: `app/public/already-got-it-docs.json` (233KB)

## 왜 파일 이름에 `browser-path` 가 붙었나

브라우저가 쓸 것과 **같은 경로**로 문서를 임베딩하기 때문이다. 자료 벡터만 만들고 질문 벡터를 다른 모델·다른 방법으로 만들면, 숫자는 나오지만 **점수가 비교할 자리를 잃는다.**

브라우저에서 `pipeline()` 을 그대로 부르면 기본 q4/q8 경로가 WASM ONNX Runtime 의 `GatherBlockQuantized` 연산을 지원하지 않아 실패한다. 그래서 역할을 나눈다 — 토크나이저는 `AutoTokenizer`, 추론은 `model_no_gather_q4.onnx` 를 ort 세션에 직접 넘긴다. **Node 스크립트도 같은 것을 쓴다**: 같은 모델 파일, 같은 `executionProviders: ["wasm"]`, 같은 mean pooling, 같은 L2 정규화.

## 고정한 것

| 항목 | 값 |
|---|---|
| 모델 | `onnx-community/embeddinggemma-300m-ONNX` |
| 파일 | `onnx/model_no_gather_q4.onnx` (q4) |
| 실행 | `executionProviders: ["wasm"]` |
| pooling | mean — `attention_mask` 가 가리키는 실제 토큰만 평균 |
| normalize | true (L2) — 정규화하면 내적이 곧 코사인 유사도다 |
| 차원 | 768 |

## 모델을 열어 보고 알게 된 것

**세션 입력은 둘뿐이다** — `input_ids`, `attention_mask`. `position_ids` 나 `token_type_ids` 는 받지 않는다.

**출력이 둘이다** — `last_hidden_state` 와 `sentence_embedding`. 명세가 "mean pooling" 을 지정했으므로 `last_hidden_state` 를 직접 평균했다. `sentence_embedding` 은 모델이 자체 pooling·dense 층을 거쳐 내놓는 값이라 결과가 다를 수 있다. **지금 바꾸지 않는다** — 어느 쪽이 나은지는 재 봐야 알고, 그건 G 의 실험이다.

## 검색 스팟체크

질문 14개(근거 있는 것 10 · 범위 밖 4)를 넣었다. 질문 벡터도 같은 스크립트로 만들었다.

| 지표 | 결과 |
|---|---|
| 근거 있는 질문 top-1 일치 | **8/10** |
| 근거 있는 질문 top-3 포함 | **10/10** |
| 범위 밖 질문이 0.55 미만 | **0/4** |

### ⚠️ 0.55 는 이 자료에서 두 무리를 가르지 못한다

| 무리 | 점수 범위 |
|---|---|
| 근거 있는 질문 | 0.633 ~ 0.792 |
| 범위 밖 질문 | 0.584 ~ 0.648 |
| **두 무리 사이 틈** | **−0.015** |

틈이 음수다. 즉 두 분포가 겹친다 — 범위 밖 질문의 최고점(0.648)이 근거 있는 질문의 최저점(0.633)보다 **높다**. 어떤 값을 임계로 잡아도 하나의 선으로는 가를 수 없다.

"내일 날씨 어때?" 가 0.584 로 나온다. 0.55 를 넘으므로 **약한 근거 경고가 켜지지 않는다.** 이 자료에서 0.55 임계는 사실상 작동하지 않는다.

이 사실이 뒤 단계로 넘기는 것:
- **F(판정)** — 범위 밖 질문의 거부는 점수가 아니라 **모델이 근거를 읽고 "없다"고 말하는 것**에 전적으로 달려 있다. 점수가 걸러 주지 않는다
- **PRD `[결정 필요]` 3** — "0.55 가 이 자료에 맞는지" 에 대한 측정이 나왔다. **맞지 않는다.** 다만 지금 바꾸지 않는다(아래)
- **PRD `[결정 필요]` 6** — "범위 밖이라고 답할 근거를 어디에 둘지" 가 더 중요해졌다

### top-1 을 놓친 2건

**"수량을 0으로 등록할 수 있나요?"** → top-1 은 `AG-004`(위시 기능, 0.633), 기대한 `AG-007` 은 3위(0.626).
`AG-007` 에는 "`owned_items.quantity`: 필수, 미입력 시 기본값 1, 1 이상 정수만 허용 (0 이하·소수는 거부)" 가 그대로 들어 있는데도 밀렸다. **의미 검색이 `owned_items.quantity` 같은 코드 표기와 자연어 "수량 0" 을 잘 잇지 못한다.** 이건 D 의 낱말 기반 검색(BM25)이 보태야 할 자리다 — 정확한 낱말이 중요한 질문에서 의미 검색이 놓치는 전형이다.

**"어제 본 D-day 랑 숫자가 다른데 왜 그래요?"** → top-1 은 `AG-003`(배지 4단계, 0.670), 기대한 `AG-012`(계산 시점) 는 3위(0.598).
[수집 기록](corpus.md#중복-가능-청크)에 적어 둔 중복 가능 1번(`AG-003` ↔ `AG-012`)이 실제로 나타났다. 둘 다 D-day 를 다루는데, 배지 쪽이 더 자주 이긴다.

**둘 다 top-3 안에는 있다.** 코사인 상위 10개를 넘기는 D 의 설계에서는 두 건 모두 근거로 들어간다. 그래서 지금 무엇도 고치지 않는다.

## 지금 고치지 않고 G 로 넘기는 것

구현 원칙에 적은 대로다 — B~F 에서 파이프라인을 손대면 무엇이 무엇을 바꿨는지 분리할 수 없다. 아래는 **G 의 실험 후보**이고, 지금 값이 기준 행이 된다.

| # | 실험 후보 | 축 | 예상 |
|---|---|---|---|
| 1 | **EmbeddingGemma 의 프롬프트 접두어를 붙인다** — 이 모델은 문서에 `title: none \| text: …`, 질문에 `task: search result \| query: …` 를 붙여 쓰도록 만들어졌다. 지금은 둘 다 맨 문장이다 | 검색 | 점수가 0.55~0.79 좁은 띠에 몰린 것이 이 때문일 수 있다. 붙이면 두 무리 사이 틈이 양수로 벌어질 것으로 본다 `[추정]` |
| 2 | `sentence_embedding` 출력을 쓴다 (지금은 `last_hidden_state` mean pooling) | 검색 | 모델 자체 pooling 이 더 나을 수 있다 `[추정]` |
| 3 | 약한 근거 임계를 0.55 에서 옮긴다 | 검색 | 지금 자료에서는 **어떤 값도 두 무리를 가르지 못한다.** 1번을 먼저 하지 않으면 이 실험은 뜻이 없다 |

순서가 있다. **1번을 먼저 한다.** 임계값(3번)은 두 무리가 갈린 뒤에야 조정할 의미가 생긴다. 임계부터 만지면 갈리지 않는 분포에 선만 옮기는 일이 된다.

## 브라우저와 같은 벡터가 나오는지

Node 쪽은 브라우저와 같은 모델 파일·같은 실행 환경(`wasm`)·같은 pooling·같은 정규화를 쓴다. 하지만 **정말 같은 값이 나오는지는 브라우저에서 돌려 봐야 확인된다.**

E 에서 앱이 질문을 임베딩할 때, 같은 문장을 양쪽에서 임베딩해 코사인이 1.0 에 가까운지 확인한다. 어긋나면 두 벡터는 다른 공간에 있고, 여기 적은 점수는 모두 뜻을 잃는다. **C 는 여기까지가 끝이 아니다** — 이 확인이 남아 있다.
