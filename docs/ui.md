## ✅ C 에서 남긴 숙제 — 브라우저와 Node 가 같은 공간인가

문서 벡터는 Node 가, 질문 벡터는 브라우저가 만든다. 둘이 다른 공간이면 지금까지 잰 모든 점수가 뜻을 잃는다.

같은 문장을 양쪽에서 임베딩해 코사인을 쟀다.

> **1.000000 — 같은 공간입니다**

화면의 「임베딩 대조」 버튼이 언제든 다시 잰다. 기준점은 `app/public/parity-anchor.json` 에 Node 가 넣어 둔 벡터다.

## 프롬프트 조립

순서를 고정했다 — **소개 → 근거 원칙 → (약한 근거 시 보수화) → `[ID]` 표시 요구 → KST 현재 시각 → `[자료]` → `[질문]`**.

근거 원칙에는 PRD 5절의 자료 밖 질문 처리 기준을 그대로 옮겼다. 개인 데이터 조회·값 판정·상태 변경을 하지 않는다는 것과, 규칙 문장을 보여 주되 "통과합니다/거부됩니다"로 판정해 말하지 않는다는 것까지 넣었다(5-3).

약한 근거 문구는 최고 유사도가 0.55 미만일 때만 들어간다. **지금까지 한 번도 들어가지 않았다** — C·D 에서 잰 대로 이 자료에서는 0.55 아래로 내려가는 질문이 없다.

## 화면에서 확인한 것

| 확인 | 결과 |
|---|---|
| `GET /api/tags` 연결 배너 | 「Ollama 연결됨 · qwen3.5:2b 준비됨」 표시됨 |
| 스트리밍 (`stream:true`, `think:false`) | 줄 단위로 파싱되어 화면에 이어 붙음 |
| 단계 표시 | 질문을 벡터로 → 근거를 찾는 중 → 답을 만드는 중 |
| 출처 칩 | `AG-004 · 주요 기능 — 위시 · vector · 0.699` + 원문 링크 |
| 칩 링크 | 옮겨진 `docs/rules/…` 주소까지 정확 |
| 중지 버튼 (AbortSignal) | 멈추고 **이미 받은 답 18자와 출처 11개가 그대로 남음** |
| 사용 조건 4단계 = README | 스크립트 대조 **4/4 같음** |

### 배너 문구를 "오류"로 쓰지 않았다

연결이 안 될 때 「오류가 발생했습니다」로 쓰면 사용자는 페이지가 고장 났다고 읽는다. 그래서 이렇게 쓴다.

> **당신 컴퓨터에서 Ollama를 켜야 합니다.**
> 브라우저가 이 컴퓨터의 Ollama 에 닿지 못했습니다. 꺼져 있거나, 이 페이지 주소가 허용 목록에 없습니다.
> 이 페이지가 고장 난 것이 아닙니다. 위 「쓰기 전에 확인할 것」 2번과 4번을 따라 주세요.

브라우저는 "Ollama 가 꺼짐"과 "출처가 허용되지 않음"을 구별해 알려 주지 않는다. 그래서 둘 다 적었다.

모델만 없는 경우는 따로 잡아 `ollama pull` 을 안내한다 — 연결과 모델은 다른 문제다.

### 사용 조건 문장을 한 곳에서 관리한다

수용 기준 6번은 "앱 소개 화면의 사용 조건 4단계가 README 와 **같은 문장**으로 보인다"이다. 눈으로 맞추면 한쪽만 고쳐진다. 그래서 문장을 `usage-steps.ts` 한 곳에 두고, `check_usage_steps.ts` 가 README 에서 같은 절을 뽑아 **글자 단위로 대조**한다. 어긋나면 0 이 아닌 코드로 끝난다.

화면에서는 `` `백틱` ``을 `<code>` 로 바꿔 보인다. 문자열 자체는 README 와 글자 그대로 같게 두고(대조 스크립트가 그 문자열을 본다), 보이는 모습만 README 의 마크다운과 맞춘 것이다.

## 열두 걸음 점검에서 채운 셋

H 로 넘어가기 전에 강의의 열두 걸음과 대조했더니 세 곳이 비어 있었다.

### ⑦ 진행률 — 195MB 를 기다릴지 판단하게 한다

모델 캐시는 있었지만 **진행률이 단계 문자열뿐**이었다. 첫 방문자는 195MB 를 받는 동안 멈춘 화면을 본다. 떠나는 자리다.

응답을 읽으면서 받은 양을 알리도록 고쳤다. `Content-Length` 가 있으면 비율까지 낸다.

> 모델 가중치(약 195MB) 내려받는 중 — **36 / 195MB** (막대 19%)

1MB 마다만 알린다 — 더 자주 알리면 화면이 떨린다. `Content-Length` 가 없으면 비율 대신 받은 양만 보인다. 캐시에 있을 때는 "받아 둔 것을 쓰므로 이번에는 기다리지 않습니다" 로 바뀐다.

**캐시를 지우고 다시 받아도 브라우저와 Node 의 코사인이 1.000000 이었다** — 받는 방식을 스트리밍으로 바꾼 뒤에도 같은 벡터가 나온다는 확인이다.

### ⑪ 근거 모달 — 화면을 떠나지 않고 원문을 읽는다

출처 칩·검색 단계·경고 배지는 있었지만 **모달이 없었다.** 근거를 보려면 GitHub 으로 나가야 했다.

칩의 ID 를 누르면 그 조각의 **원문 전체**가 열린다. 검색 방법과 점수도 함께 보인다.

`bm25` 로 들어온 조각에는 한 줄이 더 붙는다.

> 검색 방법 `bm25` · 점수 0.240 — 낱말이 겹치는 정도입니다. **1.00은 «관련 있다»가 아니라 «이 검색 안에서 1등»이라는 뜻입니다.**

D 에서 "파이썬으로 웹 크롤링" 에 서비스 개요가 1.00 으로 붙는 것을 봤다. 그 함정을 칩을 열어 본 사람이 바로 알게 한다.

### ⑫ 사람 피드백 — 자동 판정과 어긋나는지 본다

G 에서 판정의 `cited` 일치율이 0.74 로 나왔다. **자동 판정만으로는 답을 읽을 수 없다.**

「도움됨 / 아니요」를 두고, 사람의 선택이 자동 판정과 **어긋나면 그 사실을 화면에 드러낸다.**

> ⚠️ 자동 판정과 방향이 다릅니다 — 판정이 놓친 것이 있거나, 근거를 다시 볼 자리입니다.

실제로 확인할 때 바로 걸렸다. "다 쓴 물건은 어디서 볼 수 있어요?" 에 판정이 `근거 밖 진술`·20점을 줬는데, `AG-006` 이 그 답을 담고 있다. 「도움됨」을 누르자 어긋남 경고가 떴다. **이 장치가 잡으려던 것이 정확히 이런 경우다.**

### 채우지 않은 것 — 선택 엔진

Gemini 같은 대체 엔진은 넣지 않았다. 강의노트가 「💡 더 깊이」로 선택 사항이라 표시했고, PRD 3절의 비목표(서버·외부 의존을 늘리지 않는다)와도 맞는다. 「실행하지 않은 것과 이유」에 적는다.

## ⚠️ 실제로 답해 보니 — 프롬프트는 맞는데 답이 틀렸다

질문: **"위시에 담아둔 걸 샀는데 어떻게 있템으로 옮겨요?"** (수용 기준 1번)

`show_prompt.ts` 로 확인한 프롬프트는 정확했다. 순서도 맞고, **`AG-004` 가 첫 번째 자료로 들어가 있으며 그 안에 답이 그대로 있다**:

> "샀어요 · 있템으로"를 누르면 있템으로 원자적 전환

그런데 모델의 답은 이랬다.

> 제공해주신 문서상에는 **"위시리스트 전환"이나 "보유템 추가"**를 위한 구체적인 방법, API 이름, 또는 절차가 명시적으로 적혀 있지 않습니다.

세 가지가 어긋났다.

**1. 첫 번째 근거에 있는 답을 못 찾았다.** 근거 12개 중 1위 조각에 문장이 그대로 있는데도 "없다"고 답했다. D 에서 잰 대로 이 코퍼스는 근거를 10~13개나 넘긴다 — 답이 그 안에 묻힌다.

**2. 근거 원칙을 어기고 넓혀 말했다.** "문서 범위 밖으로 인정할 수 있는 **기술적 원리**만 넓히어 설명하면…" 하고는 서버 RPC 호출과 로그인 필요 여부를 지어냈다. 프롬프트에 "그럴듯하게 넓혀 말하지 말고"가 분명히 들어 있는데도 그랬다.

**3. `[ID]` 표기가 요구한 형식이 아니다.** 요구는 `[AG-004]` 인데 모델은 `[AG-005 | 위시리스트 → 보유템 전환]` 으로 썼다. **`[자료]` 블록의 표기를 그대로 따라 한 것이다.** 지시문의 예시(`[AG-004]`)보다 바로 앞에 있는 자료의 생김새가 더 강하게 작용했다.

세 번째는 4강 실습에서 본 것과 같은 구조다 — **설명문에 적어 둔 규칙보다 모델이 실제로 보는 것이 이긴다.** 그때는 "추측 금지"라고 적어도 없는 코드를 발명했고, 문제를 없앤 것은 지시문이 아니라 호출 전 검사였다.

### 지금 고치지 않는다

구현 원칙대로다. 지금 프롬프트를 손보면 이 값이 기준 행이 될 수 없고, 무엇이 무엇을 바꿨는지 분리할 수 없다. G 의 실험 후보로 넘긴다.

| # | 후보 | 축 | 예상 |
|---|---|---|---|
| 7 | `[자료]` 블록의 표기를 `[AG-004]` 로 바꾸고 섹션은 다른 줄에 둔다 | 프롬프트 | 인용 형식이 요구와 맞을 것 `[추정]` — 지시문 대신 모델이 보는 것을 바꾸는 접근 |
| 8 | 근거 개수를 줄인다 (D 후보 6번과 같은 자리) | 검색 | 답이 근거 뭉치에 묻히는 것이 줄어들 것 `[추정]` |
| 9 | 근거 원칙 문구의 위치를 자료 **뒤**로 옮긴다 | 프롬프트 | 지금은 원칙이 4,000자 앞에 있다. 질문 가까이 두면 지켜질 확률이 오를 것 `[추정]` |

7번과 9번은 같은 관찰(모델은 가까이 있는 것을 따른다)에서 나왔지만 서로 다른 곳을 건드린다. 한 번에 하나만 바꾼다.

## F 로 넘기는 것

이 답은 판정에 넣으면 이렇게 나와야 한다 — `grounded:false`(근거에 있는데 없다고 했다), `noHalluc:false`(서버 RPC 절차를 지어냈다), `cited` 는 형식에 따라 갈린다, `refusal:false`(근거가 있으므로 정당한 거부가 아니다).

**판정이 이 답을 통과시킨다면 판정 자체를 의심해야 한다.** F 의 첫 확인 지점이다.
